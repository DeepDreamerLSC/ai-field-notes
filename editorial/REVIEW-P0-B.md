## 1. 结论：保留，推荐为首条试片

- **痛点识别零成本**：所有迭代过 Agent/Prompt 的人都经历过"这轮好像更好了"，8 秒内即可建立冲突，无需铺垫。
- **视觉结构最简单**：整条视频的叙事可以由一张"同一改动、双结局分叉图"承载，最符合试点期"一套有限模板"的约束。
- **证据基础最扎实**：来自已发生的评测与缺陷归因实践（Fact 级），且自带诚实边界（轻量任务不必建平台），能扛住专业观众的审视。
- **种子受众反馈质量最高**：AI 产品经理 / 技术负责人是频道冷启动期最可能评论、收藏、转发乃至咨询的群体，正好回答 Issue #1 想测的"受众反馈差异"。

## 2. 受众 / 带走 / 核心观点 / 最强反对

- **精确受众**：正在迭代 Agent / Prompt 的 AI 产品经理与小型技术团队负责人，尤其是困在"改一版 → 跑几条 → 感觉不错 → 上线"循环里的人。
- **看完带走的一件事**：把"感觉更好了"这句话，换成"哪类失败消失了、用什么样本复测的"。
- **核心观点**：没有可复测的失败样本和固定判据，Prompt 迭代就是随机游走。最小"尺子"六步：**失败记录 → 可观测行为定义 → 区分性样本 → 可重复测量 → 对照 → 受控改动**。
- **最强反对观点**：「做 eval 太重了，小团队没资源；连模型公司都评不准。」
  - 视频内应对（必须主动说出来，不能只写在文档里）：不主张人人建 eval 平台；一次性、低风险任务用 5–10 个样本的固定清单就够。"尺子"要的不是平台，是**固定的样本 + 固定的判据**——一张表格也可以。这个边界让观点对专业观众更可信。
- **证据局限**：无可公开的具体失败数字、任务名或截图，全部用自制合成示例并标"示例"。

## 4. 标题与 Hook

候选标题：

1. 《你说这版 Prompt 更好了？你怎么知道？》
2. 《改了一个月 Prompt，你可能只是在随机游走》

**Hook（约 8 秒）**：「"这轮 Prompt 我调好了。"——好。那上一轮修掉的那个 bug，这轮还在吗？」

## 5. 旁白大纲（约 105–115 秒）

1. **Hook**（0–8s）：对话式反问进场。
2. **熟悉的循环**（8–25s）：改 prompt → 跑三条 → 看起来不错 → 上线 → 老问题换个方式回来 → 再改。每个人都在这圈里。
3. **问题本质**（25–45s）：单次通过 ≠ 稳定。你缺的不是更多灵感，是一把尺子——没有它，"更好了"只是抽样运气。
4. **最小尺子六步，重点讲三样**（45–85s）：
   - 失败记录：把每次翻车写成一句话，攒成清单；
   - 区分性样本：老失败 + 新任务各留一组，每次改动前后同跑；
   - 对照：一次只改一个变量，其余不动。
   （行为定义、可重复测量、受控改动一句带过，口播不逐条展开。）
5. **边界声明**（85–100s）：不是让你建 eval 平台。一次性、低风险任务，5 个样本的固定清单就够。
6. **收尾**（100–110s）：下次说"更好了"之前，先说"哪类失败消失了"。

## 7. 公开安全检查

- 全部示例使用通用合成任务（如"发票号提取"一类），片内标注"示例"；不提任何内部项目名、任务名、数据。
- 不引用私有仓库 Issue/PR、日志、trace、截图。

## 8. 工作量与风险

- 首条成片（含模板一次性开发 4–6 h）：脚本 40 min、分镜 30 min、渲染调参 1–2 h、配音 + 校对 30–60 min、审校 40 min，**首条总计约 6.5–9 h**。
- 模板建成后单条复用成本约 2.5–3.5 h。
- 风险：①六步若平铺直叙会像说教——必须让"分叉图"承载叙事，而不是念清单；②TTS 对"判据、归因、回归"等词的发音需逐一试听，不达标就人工配音；③标题 2 有轻微冒犯感，投放时优先标题 1，按数据再试。
