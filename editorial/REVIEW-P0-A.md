## 1. 结论：保留（微调）

保留理由：三条里受众面最广，针对的误区（"要 Agent = 选模型"）出现频率最高，是检验"企业经营视角"是否有流量的最佳试金石——这正是 Issue #1 想测的受众差异之一。

微调理由：工作标题是"为什么不是 X"的否定句式，偏说教。建议标题与主线落在具体动作上（"我会先问三件事"），把否定留给 hook 用。

## 2. 受众 / 带走 / 核心观点 / 最强反对

- **精确受众**：正被 AI 焦虑推动、身边有人建议"上 Agent"的中小企业经营者与业务负责人（约 50–500 人规模的一号位/二号位）；次级受众是替老板做调研的运营/产品负责人。
- **看完带走的一件事**：接到"我们要做 Agent"的需求时，先要一张现行工作流图，再谈模型。
- **核心观点**：Agent 是自动化手段的最后一格，不是第一格。先把流程拆成"确定性任务 / 语义任务"，再决定用普通自动化、LLM 组件，还是真的需要 Agent。
- **最强反对观点**：「先跑起来再说，demo 失败也是学习；前置分析太重，企业永远启动不了。」
  - 视频内应对：不否认快速验证，把"最小验证工作负载"定位成快速启动的正确姿势——验证对象是工作流切片，不是模型选型。
  - 次级反对：「模型越来越强，直接套 Agent 平台就行。」→ 用任务分类回应：强模型改变的是语义任务的成本，不改变数据、权限、指标这三个前置问题。
- **证据局限**：没有可公开的"先选模型导致失败"的真实案例，只能抽象示意，必须标"示例"。

## 4. 标题与 Hook

候选标题：

1. 《客户说"给我们做个 AI Agent"，我先问这三个问题》
2. 《想做 AI Agent 的企业，第一步不是选模型，是画这张图》

**Hook（约 8 秒）**：「老板说要个 AI Agent。这个阶段最贵的一句话，其实是——"我们用哪个模型？"」

## 5. 旁白大纲（约 110–120 秒）

1. **Hook**（0–8s）：反问进场。
2. **熟悉的错误路径**（8–30s）：需求 → 选模型 → 搭 RAG → 上框架 → demo 惊艳 → 上线后失控。点破：每一步都在回答"怎么做"，没有人回答"做什么、算成功"。
3. **正确的第一步：三个问题**（30–70s）：① 这段流程今天没有 AI 时，人是怎么做的？（工作流）② 哪些步骤是确定性规则、哪些需要理解语义？（任务性质）③ 结果怎么衡量改善？（指标）
4. **判断树**（70–100s）：全确定性 → 普通自动化就够；局部语义 → 一个 LLM 组件；需要跨多步的自主决策与工具调用，才轮到 Agent。
5. **收尾**（100–118s）：Agent 是最后一格，不是第一格。预告下期：怎么切"最小验证工作负载"。
