# 内容沉淀流程

## 总体流程

```
项目事实
   ↓
内部复盘
   ↓
提炼核心问题
   ↓
判断是否具有公开价值
   ↓
脱敏整理
   ↓
内容草稿
   ↓
发布
```

## 内容进入标准

满足以下任一条件即可进入整理：

- 解决了真实问题
- 产生了反直觉结论
- 改变了原有技术判断
- 可以帮助其他团队避免类似错误
- 有方法论价值

## 不适合发布

以下内容不直接进入：

- 未验证的技术观点
- 客户敏感数据
- 内部权限信息
- 仅有工具介绍，没有实践判断的内容

## 每篇内容建议记录

```yaml
标题:
来源项目:
来源问题:
内容类型:
核心观点:
支撑事实:
限制条件:
状态:
```

## 三层表达

### 第一层：事实

发生了什么。

### 第二层：判断

为什么这样判断。

### 第三层：方法

未来遇到类似问题如何处理。
